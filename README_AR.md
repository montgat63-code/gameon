# GameMaster — الهيكل النظيف من الصفر

هذا المستودع هو نقطة البداية الجديدة لـGameMaster. لا يعتمد على إصدارات v5–v9 ولا يحتوي جسر Scrcpy اليدوي داخل المسار الإنتاجي. الهدف هو بناء تطبيق Windows احترافي حول عميل Scrcpy الرسمي المطابق، مع واجهة Gaming، Profiles، محرر مفاتيح، إعدادات أداء، وتشخيص واضح.

## طريقة العمل المجانية

يُرفع المستودع إلى GitHub. تُستخدم Codespaces من المتصفح لكتابة الكود حتى لا يستهلك اللابتوب الضعيف عملية البناء. يُستخدم Jules لمهام كبيرة محددة على المستودع. تُستخدم GitHub Actions لتشغيل الاختبارات وبناء ZIP/EXE سحابيًا. يمكن استخدام Amazon Q من بيئة التطوير لمراجعة الملفات وتشغيل الأوامر، لكنه ليس خدمة تعمل في الخلفية نيابةً عن المستخدم.

## مبدأ مهم

لا نعيد تنفيذ بروتوكول Scrcpy الخاص ولا نفك الفيديو يدويًا في Python. تُضاف ملفات `scrcpy.exe` الرسمية والخادم المطابق داخل `tools/official-scrcpy` بعد إعداد المستودع. GameMaster يدير العملية والواجهة والإعدادات، ويترك الفيديو والتحكم للعميل الرسمي.

## الحالة الحالية

هذه النسخة هي هيكل نظيف فقط. لم تُعلن أي ميزة مكتملة بعد. ستُضاف كل ميزة مع اختبار ومعيار قبول، ثم تُبنى نسخة Windows عبر GitHub Actions.

## مراحل البناء

1. إنشاء العقود وحالات الاتصال واختبارات الوحدات.
2. إضافة مدير ADB واكتشاف الأجهزة.
3. دمج عميل Scrcpy الرسمي ومراقبة العملية.
4. بناء الواجهة واللوحات والتكبير وإخفائها.
5. إضافة Profiles ومحرر المفاتيح والتعافي من الأعطال.
6. إضافة اختبارات السحابة وبناء Windows.
7. اختبار USB والهاتف الحقيقي قبل إصدار Release.

## التشغيل المحلي بعد اكتمال النواة

```bat
run.bat
```

لا تشغّل التطبيق قبل وجود `tools/official-scrcpy/scrcpy.exe` وملفات العميل التابعة. سيمنع المشغل التشغيل الناقص ويعرض اسم الملف المفقود.

## الأمان

لا تضع كلمات مرور أو مفاتيح API أو بيانات الهاتف في المستودع. لا تمنح خدمات البناء صلاحيات حذف شاملة. أبقِ المستودع خاصًا إذا كان الكود أو ملفات Profiles شخصية.
