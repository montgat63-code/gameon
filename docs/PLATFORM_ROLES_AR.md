# متى نستخدم كل منصة؟

## GitHub

GitHub هو المصدر المركزي الوحيد للكود. نرفع إليه الهيكل، التغييرات، Issues، وسجل الإصدارات. لا ننشئ نسخًا متفرقة باسم v5 وv6 وv7؛ كل تغيير يدخل عبر Commit واضح أو Pull Request.

## GitHub Codespaces

نستخدم Codespaces عندما نريد العمل من الهاتف أو اللابتوب الضعيف. يفتح محررًا وطرفية على خادم سحابي، لذلك لا يقوم اللابتوب ببناء PySide6 أو تشغيل أدوات الذكاء الاصطناعي الثقيلة. Codespaces ليس مكان اختبار USB؛ هو مكان كتابة وفحص الكود.

## Jules

نستخدم Jules للمهام التي تحتاج تحليل مستودع أو تعديل عدة ملفات. كل طلب يجب أن يكون محددًا، مثل: "حلل طبقة Profiles وأضف اختبارات الهجرة". نراجع التغيير قبل دمجه، ولا نطلب منه بناء المنتج كاملًا في رسالة واحدة.

## Amazon Q Developer

نستخدم Amazon Q كمساعد داخل Codespaces أو الطرفية لمراجعة خطأ، تشغيل اختبار، أو تنفيذ إصلاح صغير. لا نعطيه صلاحيات حذف شاملة، ولا نضع أسرارًا داخل السياق.

## GitHub Actions

تعمل Actions تلقائيًا عند Push أو Tag. تشغّل compile وpytest وsmoke، ثم تبني نسخة Windows على `windows-latest` وتضع ZIP في Artifacts. إذا فشل اختبار واحد، لا تنتج Release.

## اللابتوب والهاتف

يُستخدم اللابتوب في النهاية لتشغيل النسخة الجاهزة فقط، ويُستخدم الهاتف لاختبار USB Debugging وADB وScrcpy والاستجابة الفعلية. هذه الخطوة لا يمكن استبدالها بالكامل بالسحابة.

## التسلسل الصحيح

```text
GitHub repository
      ↓
Codespaces للكتابة من المتصفح
      ↓
Jules أو Amazon Q لمهمة محددة
      ↓
Pull Request ومراجعة
      ↓
GitHub Actions للاختبارات والبناء
      ↓
ZIP/EXE للتنزيل
      ↓
اختبار اللابتوب والهاتف الحقيقي
```
